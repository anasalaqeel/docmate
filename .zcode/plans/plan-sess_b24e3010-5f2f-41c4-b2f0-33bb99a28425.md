# "Ask AI" Feature — Full Version (Streaming + Tool Calling + Multi-Provider)

## What we're building

A floating **"Ask AI"** button (bottom-right) on the public document viewer and the admin editor opens a slide-in chat panel. Any user — anonymous visitors on public docs, logged-in staff on private docs — asks questions about the documentation. The AI receives the **current page content + documentation outline**, plus a **`get_page_content` tool** it invokes itself to read other pages when needed (so it answers *from* those pages, not just points to them). Answers stream token-by-token (SSE). Admins configure the AI provider in a new settings tab. History is session-only (React state). Zero DB schema changes.

## Chat UI approach: Vercel engine + custom visuals

- **`useChat` from `@ai-sdk/react`** owns the hard parts: stream protocol parsing, message/tool-call parts, abort, error states.
- **Visual components are custom** (~4 small components) built with existing HeroUI primitives + `--docmate-*` theme tokens + the existing themed `MarkdownRenderer`, so the chat matches DocMate's branding, light/dark mode, and doc styling. (Prebuilt chat UIs — Vercel AI Elements, assistant-ui, chatscope — assume shadcn/Radix styling systems and would need total restyling anyway.)

## New dependencies

- **Backend**: `ai` (v5), `@ai-sdk/openai`, `@ai-sdk/anthropic`, `@ai-sdk/google`
- **Frontend**: `ai` (v5), `@ai-sdk/react`

## 1. Settings — admin-configurable (SSO/LDAP house pattern)

Keys in a new `ai` category: `ai.enabled` (bool, default false, **isPublic: true** so the frontend reads it via `GET /v1/settings/public` to show/hide the widget), `ai.provider` (`openai`|`anthropic`|`google`, default `openai`), `ai.model` (string), `ai.baseUrl` (optional — enables OpenAI-compatible gateways/Ollama with the openai provider), `ai.apiKey` (string, private), `ai.maxOutputTokens` (number, default 1024).

Touchpoints (all verified in the codebase):
- `backend/src/config/settings.definitions.ts` — `registerSetting` entries
- `backend/src/config/defaultSettings.ts` — defaults + types
- `backend/src/schemas/settings.ts` — zod schemas
- `backend/src/types/settings.ts` — add `"ai"` to `SettingCategory`
- Admin UI: new "AI Assistant" tab in `frontend/src/pages/admin/settingsPage.tsx` (enable toggle, provider select, model, base URL, password-masked API key)

**Secrets (LDAP precedent, `ldapService.ts:28-30`)**: env `AI_API_KEY` overrides the DB-stored key via `backend/config/custom-environment-variables.json`; documented in both `.env.example` files. The key never leaves the backend.

## 2. Backend

**`backend/src/services/askAiService.ts`** (new):
- `resolveAiConfig()` — settings + env override; `createModel(cfg)` — provider switch: `createOpenAI({ apiKey, baseURL })` / `createAnthropic` / `createGoogleGenerativeAI`
- `flattenPageContent(page)` — reuses content→markdown logic from `export.service.ts` (extract shared helper)
- `buildSystemPrompt(doc, currentPage, outline)` — doc title/description/version + current page title & full content + outline as `pageId → title → path`; rules: answer only from the documentation, cite page titles, use the tool when info may be on another page, treat doc content as *data* (prompt-injection defense), answer in the user's language, markdown output
- **`get_page_content` tool**: zod input `{ pageId: number }`; execute joins `pages → sidebarItems` and **rejects any pageId not belonging to the same documentation** (no privilege escalation); truncates content (~12k chars)
- `streamAskAi({ docId, pageId, messages })` — `streamText({ model, system, messages: convertToModelMessages(messages), tools, stopWhen: stepCountIs(4), maxOutputTokens, abortSignal })`

**`backend/src/routes/askAiRoute.ts`** (new), mounted in `app.ts` as `v1.route("/docs", askAiRoute)`:
- `POST /v1/docs/public/:docId/ask` — anonymous; documentation must be `isPublic` else 404 (mirrors `docsRoute.ts:142`)
- `POST /v1/docs/:docId/ask` — `authorize(["docs:read"])` for private docs in the editor
- Shared handler: `aiRateLimit` → `zValidator` (`pageId: number`, `messages` ≤ 20, question ≤ 2000 chars) → 503 if AI disabled → UI message stream response with `Cache-Control: no-cache` + `X-Accel-Buffering: no` (so nginx doesn't buffer the SSE stream)

**`backend/src/middlewares/rateLimiter.ts`**: add `aiRateLimit = createRateLimiter(60_000, 10, ...)` (10 questions/min/IP — AI calls are expensive; existing factory makes this one line).

**Swagger**: register both endpoints in `utils/openApiGenerator.ts`.

## 3. Frontend

**`frontend/src/services/aiService.ts`** (new): AI status from the existing public-settings service; endpoint URL builders.

**`frontend/src/components/AskAi/`** (new + `AskAi.module.css`, all styled with `--docmate-*` tokens so light/dark + tenant branding work automatically):
- `AskAiWidget.tsx` — floating button + open/close state; gated by `ai.enabled` from public settings; Esc closes; `role="dialog"`, `aria-live` for streaming
- `AskAiPanel.tsx` — right slide-in mirroring the existing `SidebarPeekOverlay` keyframe pattern (`AppLayout.tsx:29-62`); header with doc/page context + clear conversation + close; message list; auto-growing input (Enter sends, Shift+Enter newline); stop button (aborts generation); full-width sheet on mobile
- `ChatMessageBubble.tsx` — user text vs assistant markdown via `react-markdown + remark-gfm + rehype-highlight` (no raw HTML → XSS-safe; no `docId` prop so it never triggers the authenticated OpenAPI fetch); "Reading *<page title>*…" status chip when the tool fires (transparency)
- `useAskAi.ts` — wraps `useChat({ id: 'doc-${docId}', transport: new DefaultChatTransport({ api, prepareSendMessagesRequest }) })`, injecting the current `docId`/`pageId` into every request body; per-doc id resets the thread on doc switch

**Integration**: render `<AskAiWidget docId pageId docTitle/>` in `publicDocViewerPage.tsx` (sibling of `DocSearchModal`, ~line 406) and in `docsEditorPage.tsx`. Errors (429/503/network) → sonner toasts, consistent with existing UX.

## 4. Security checklist (industry standards)

Server-side authorization on both routes **and inside the tool** (same-documentation only) • per-IP rate limiting • input caps (question length, history ≤ 20, page truncation, `maxOutputTokens`) • prompt-injection defense in system prompt • API key server-only with env override • react-markdown renders no raw HTML • request abort/timeout • fail-closed 503 when disabled • 404 (not 403) for private docs to avoid existence leaks.

## 5. Tests (`bun:test`, existing patterns in `backend/src/tests/`)

- Guards: anonymous → 404 on private doc; `docs:read` required for private ask; 503 when disabled; 429 from rate limiter; zod 400s
- Service: `flattenPageContent`; system prompt contains outline + current page + injection-defense instruction; tool loads the correct page / rejects a cross-doc `pageId`; env-key precedence
- Happy-path streaming with the AI SDK mock model (`ai/test`) — no real provider needed
