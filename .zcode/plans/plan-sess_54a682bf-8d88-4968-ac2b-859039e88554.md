# Docmate — Documentation Versioning (Docusaurus/ReadMe model, verified against code)

## Semantics (what "version" means after this change)

- **Live content** (today's `sidebar_items` + `pages` + `openapi_specs` tables) remains the working copy editors change — exactly as today. Docs with no versions behave 100% unchanged.
- **Cut a version** = freeze the complete content set (doc meta + sidebar tree + page contents + latest OpenAPI spec) into an immutable JSONB snapshot row, like `docusaurus docs:version 2.0.0`.
- **Stable default**: at most one version per doc flagged `isDefault`. `GET /v1/docs/public/:id` serves that snapshot (readers get stable content; editors keep working on live). With no default, it serves live as today. `documentations.version` label is synced to the default label so doc cards stay consistent.
- **Reader addressing**: `/docs/:id` = default (or live); `/docs/:id/v/:version` = a specific snapshot; `/docs/:id/v/next` = live draft (only meaningful when a default exists). Page routes mirror this (`/v/:version/page/:pageId`).
- **Fork to edit**: copies a snapshot back over live content (ID-preserving upsert in one transaction), so an old version can be fixed and re-cut. Standard "restore" flow (Docusaurus copy-back / ReadMe fork).
- Snapshots are immutable and include original row IDs — reader URLs and page attachments keep working on old versions.

## Backend (Bun + Hono + Drizzle, all patterns verified in code)

### 1. `backend/src/db/schema.ts` — new table (house style: array-form constraints, named uniques, relations, `$inferSelect` type export)

```
documentation_versions: id serial PK, documentationId FK→documentations onDelete cascade notNull,
  version varchar(50) notNull, changelog text, snapshot jsonb notNull, isDefault boolean notNull default false,
  isBackup boolean notNull default false, createdBy FK→users, createdAt/updatedAt (defaultNow + $onUpdate like every table)
  unique("documentation_versions_doc_version_unique").on(documentationId, version)
  uniqueIndex("documentation_versions_one_default_per_doc").on(documentationId).where(sql`is_default = true`)
+ relations (documentation, creator) and `versions: many(...)` on documentationsRelations
+ export type DocumentationVersion
```

Apply with `bun run db:push` (project convention — drizzle-kit push, no migration files; additive table, zero data risk).

### 2. New `backend/src/services/version.service.ts` — all version logic in one service

Snapshot format (flat, full rows — chosen so serving reuses `buildHierarchicalTree` unchanged and fork can restore every column):
```ts
{ documentation: {title, description, version, type, baseUrl, showApiEndpointsInSidebar},
  sidebarItems: Array<SidebarItem & { page: Page | null }>,   // active (deletedAt null) items
  openApiSpec: OpenApiSpec | null }                            // latest by updatedAt, matching every read path
```

- `createVersion(docId, {version, changelog, isDefault, isBackup}, userId)`: queries exactly like `GET /public/:id` does (doc + sidebarItems `with: page` + latest spec), builds the snapshot, inserts. Label validated `^[a-zA-Z0-9][a-zA-Z0-9._-]{0,49}$`, **"next" reserved (case-insensitive)**, duplicates → 409. If `isDefault`: clears other defaults and syncs `documentations.version` to the label (same transaction).
- `listVersions(docId, {includeBackups})` — metadata only, never selects the `snapshot` column (can be MBs).
- `setDefault(docId, versionId)` / `deleteVersion` (deleting the default just leaves no default → plain URL falls back to live).
- `getPublicVersionData(docId, label)`: returns the same response shape as `GET /public/:id` — `{...snapshot.documentation, id: doc.id, isPublic/createdAt/updatedAt/creator from live row, sidebarItems: buildHierarchicalTree(snapshot.sidebarItems), openApiSpec, viewedVersion: {id, version, changelog, isDefault, createdAt}}`; `"next"` label serves live tables (viewedVersion marker only). Used by both new public endpoints.
- `forkToLive(docId, versionId)` — single `db.transaction` (postgres-js pool supports it), **ID-preserving** because `uploads.pageId` is `onDelete: cascade` (delete+recreate would wipe attachments) and reader URLs embed page IDs:
  1. Upsert each snapshot sidebar item by id (existing row → UPDATE all columns incl. `deletedAt: null` — revives trashed items in the version; missing → INSERT with explicit id, **parents before children**, order computed topologically from `parentId`, never trusting the denormalized `level`).
  2. Same upsert-by-id for pages (slug/content/metadata/dates; JSONB dates → `new Date()` for timestamp columns).
  3. Hard-DELETE **active** items of this doc not in the snapshot (their pages/uploads cascade — correct, those pages cease to exist). Soft-deleted (trash) rows untouched.
  4. OpenAPI: snapshot spec → delete all spec rows for doc, insert snapshot row (mirrors existing `DELETE /:id/openapi` + insert); no spec → delete all.
  5. `SELECT setval(pg_get_serial_sequence('sidebar_items','id'), COALESCE(MAX(id),0)+1, false)` and same for `pages` so future inserts don't collide.
- `createIngestionBackup(docId)`: used by ingestion — backup label `backup-<yyyymmdd-HHMMSS>`, `isBackup: true`, then prune to newest 5 backups.

### 3. `backend/src/routes/docsRoute.ts` — new endpoints (manual validation + `{success,data|message}` envelope + try/catch, matching this file's existing style; no route conflicts since segment counts differ)

Admin (mounted under `/v1/docs`):
- `GET /:id/versions` — `docs:read`; list incl. backups flag (no snapshot blobs)
- `POST /:id/versions` — `docs:update`; body `{version, changelog?, isDefault?}` → cut
- `PATCH /:id/versions/:versionId` — `docs:update`; `{changelog?, isDefault?}` (label immutable — it's in URLs); `isDefault: true` demotes others
- `DELETE /:id/versions/:versionId` — `docs:delete` (consistent with doc delete / trash permanent delete)
- `POST /:id/versions/:versionId/fork` — `docs:update`

Public (no auth, `isPublic` enforced, like existing public routes):
- `GET /public/:id/versions` — labels + isDefault + changelog + createdAt (backups excluded) for the dropdown
- `GET /public/:id/versions/:version` — full doc-shaped snapshot via `getPublicVersionData`

**Modified**: `GET /public/:id` — after loading live doc, if a default version exists, serve its snapshot via the same helper; response gains additive `viewedVersion`, `openApiSpec`, and `versions` (label list, embedded so the viewer needs no extra round-trip; selector hidden when empty). No default → byte-identical behavior to today plus the additive fields. Admin `GET /:id` stays live-only (editors always edit the working copy).

### 4. `backend/src/routes/externalDocsRoute.ts` — one added line of behavior

`POST /ingest-markdown` calls `importService.replaceSidebarContent`, which hard-deletes all items/pages/specs (verified in `import.service.ts`). Before it runs: `versionService.createIngestionBackup(doc.id)` — the versioning infra makes the destructive ingestion recoverable. `/ingest` (OpenAPI upsert) is non-destructive, untouched.

## Deliberate decisions & stated limitations
- **JSONB snapshots, not a `versionId` column on every table**: matches Docusaurus `versioned_docs` / WP revisions / ReadTheDocs frozen builds; zero risk to the 15+ existing flows (ingestion, trash, search, AI, export, attachments) that all assume today's live schema. Fully editable parallel versions (Antora-branch model) would be a rewrite of every sidebar/page/spec query — rejected as over-engineering for v1.
- Out of scope, explicitly: per-version export, version-diff UI, version-aware Ask AI, editing a version in place (fork covers it).
- `documentations.version` stays one column: mirrors the default label when set (reader-facing cards), remains the live label otherwise (Settings tab behavior unchanged).
