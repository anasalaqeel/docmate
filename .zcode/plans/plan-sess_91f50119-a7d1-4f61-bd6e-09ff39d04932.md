# Doc title in the navbar for the public doc viewer

## Approach
Yes — adopt your idea. The topbar carries the document identity; the sidebar becomes pure navigation. This kills the current duplication (doc title shows in sidebar header AND breadcrumb) and survives sidebar collapse (title stays visible even when the nav rail is collapsed to icons).

## Changes

**1. Reintroduce a navbar context slot in the layout** (`src/types/layout.ts`)
- Add `navbarTitle?: string` and `navbarSubtitle?: string` to `LayoutData` (scoped, optional — pages that don't set it get nothing, so the old "every page crams its title into the brand" problem doesn't return).

**2. AppLayout navbar** (`AppLayout.tsx` + `.module.css`)
- When `layoutData.sidebar` exists, render after the hamburger toggle: a vertical divider, then `navbarTitle` as a medium-weight text (truncated with ellipsis on narrow screens) with optional `navbarSubtitle` small text underneath.
- Pages without sidebar keep the brand lockup exactly as now.

**3. publicDocViewerPage** (`publicDocViewerPage.tsx`)
- Set `navbarTitle: doc.title`, `navbarSubtitle: \`v${doc.version}\`` (or the creator name) in its `setLayoutData` call.

**4. DocSidebar slim-down** (`DocSidebar.tsx` + `publicDocViewerPage.module.css`)
- Header reduces to the org brand row only — remove the doc title row, version pill, and creator line (title/version now live in the navbar; creator already shows in the welcome section).
- Tree area gains a "Pages" section label, matching the existing "API Reference" label, so the sidebar reads as a clean two-section nav.
- Collapsed mode already shows just the logo — unchanged.

**5. Breadcrumb stays** in the content area (page-level context `docs / {doc} / {page}`); with the title in the navbar this is now complementary, not redundant.

## Verify
`tsc --noEmit` + `bun run build`; confirm no layout shift between viewer pages (title slot only present when a doc is loaded).
